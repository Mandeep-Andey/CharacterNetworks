# NLP Pipeline Schema Update — Frontend Impact Report

## 1. Overview
The NLP data pipeline (GE_LLM_V4) has introduced a formal, rigorous schema consisting of pre-computed graphs (`graph_data.json`), enriched interaction records (`interactions_enriched.jsonl`), and standalone metrics (`graph_metrics.json`).

Currently, the React frontend (`src/context/DataContext.tsx`) expects a legacy structure (`combined_chapters_all_books_1_86_merged_final.json`), where data is nested cleanly by chapter string, containing unnormalized character names and inline evidence snippets.

To align the frontend with the `GE_LLM_V4` data contracts, the codebase must undergo several significant architectural and data-fetching updates.

## 2. Core Differences & Schema Analysis

### Old Schema vs. New Schema

| Feature | Current Frontend Implementation | New NLP Pipeline (v4.0 Schema) |
| --- | --- | --- |
| **Top-Level Structure** | Dictionary keyed by Chapter ID. | Flat `GraphData` container with `nodes`, `edges`, and `scenes` arrays. |
| **Character Identity** | Handled on the client with `resolveName` and `aliases.json`. | Handled server-side. Nodes have Canonical `character_id` and `display_name`. |
| **Edge Storage** | Grouped by chapter. Re-calculated dynamically in `DataContext.tsx`. | Global `edges[]` array. Each edge maps to a `chapter_num` and `scene_id`. |
| **Interaction Evidence** | Snippets stored inline (`evidence_snippet`). | `Edge` contains `quote_ids` (TEI XML anchors) resolving to canonical evidence. Enriched evidence requires parsing `interactions_enriched.jsonl` or loading the indexed TEI elements. |
| **Edge Weights** | Computed sequentially via array loops in frontend. | Pre-computed as the `weight` property in the `Edge` model. |
| **Community / Groups** | Custom dictionary `middlemarch_characters_grouped.json` and client-side Louvain calculation. | Pre-computed Louvain communities available in `graph_metrics.json`. |
| **Confidence / NLP Metrics**| Non-existent. | Each Edge has `attribution_method` and `confidence` score (e.g. 0.97 for BookNLP matches). |

## 3. Required Codebase Changes

### A. Data Fetching and Context (`DataContext.tsx`)
1. **Refactor Initial Load Strategy**:
   Instead of iterating over chapters in a nested dictionary, the app must load `graph_data.json` globally and index the resulting list of `edges`.
2. **Remove Runtime Entity Resolution**:
   Delete the `resolveName` local helper, the `aliasMap`, and `aliases.json` usage. `character_id` must be used strictly as the primary node key.
3. **Migrate Structural State**:
   - `ChapterData` type will need refactoring to dynamically filter `GraphData.edges` by `chapter_num`. 
   - `BookChapters` type can be derived by grouping `GraphData.scenes` iteratively or extracting unique combinations of `book_num` and `chapter_num` present in `GraphData.edges`.

### B. Graph State & Interaction Snippets
1. **Evidence Display (Tooltip)**: 
   Currently, the tooltip reads `interaction.evidence_snippet`. The new schema provides `quote_ids`. To display text in tooltips, we will need either:
   - A secondary request or lookup table that maps `quote_id` -> snippet text (can be pre-generated by the pipeline).
   - Fetching and parsing `interactions_demo.jsonl` to provide a lookup dictionary of interaction events, matching by `source`, `target`, and `chapter_num`.
2. **Support Different Edge Types**: 
   The new `Edge` structure introduces `edge_type` (`dialogue`, `co_presence`, `mention_in_absence`). We should implement visual treatments in D3 (e.g., solid line vs. dashed line) to support this.

### C. Types (`src/components/graph/types.ts`)
1. **Update `Node` interface**: 
   Reflect Tier 1 data features: `character_id` (formerly `id`), `display_name`, `gender` (for color coding?), `is_deceased`.
2. **Update `Link` interface**: 
   Needs to map D3 `source`/`target` directly to the `character_id` values, while attaching `edge_type`, `attribution_method`, `confidence`, and `sentiment_polarity` (Tier 2 metric).

### D. Sub-Components
1. **Graph Controls / UI**:
   - We must update components like `AnalysisPanel.tsx` or `NodeDetailsPanel.tsx` to handle the new extended Tier 1 and Tier 2 properties.
   - We can add visual toggles to filter relationships by `edge_type` (e.g., "Mute co-presence interactions" or "Show only dialogue").
   - We can filter graph edges using the new `confidence` value or `attribution_method` properties to let researchers toggle heuristic vs. LLM relationships.

## 4. Implementation Plan (Next Steps)

1. **Obtain Data Artifacts**: Download `graph_data.json`, `graph_metrics.json`, and an evidence lookup dictionary from the compiled NLP pipeline.
2. **Scaffold Types**: Create an isolated `src/types/schema.ts` file accurately reflecting the Pydantic v2 schemas.
3. **Refactor Context**: Update `DataContext.tsx` to load `graph_data.json`. Filter by chapter correctly on-the-fly or via pre-processed grouping.
4. **Fix Network Rendering**: Map `D3ForceGraph.tsx` access variables to `display_name` and `character_id`.
5. **Restore UI Overlays**: Hook the evidence snippet engine up to correctly use `quote_ids` or an enriched interaction lookup table.
